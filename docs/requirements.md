### 2.1 Domain data categories vs producing operations (source-grounded gap analysis)

Domain description (verbatim, Тема 4): «Отдел снабжения в каждый момент времени должен
иметь точные данные о названии товаров, их количестве на складе, о названии магазинов,
о названии и количестве каждого вида товара в каждом магазине, о заявках магазинов
на текущий год».

| Data category (domain) | Produced/updated by |
|------------------------|---------------------|
| product names, warehouse quantity | FR-1, FR-2, FR-5 |
| store names | FR-3, FR-4 |
| product name + quantity per store | **none of the seven operations** |
| store requests (заявки) for the current year | **none of the seven operations** |

The assignment is internally incomplete: two required data categories have no creating
operation. The «Разработать» tail («модули ввода, изменения и просмотра данных») grounds
the reconstruction of the missing operations. They will be recorded as **derived
requirements** (FR-8+): traced to the assignment text, but not among the seven named
operations — kept separate from both original requirements and project extensions.
FR-7 stays reserved for its operation and is deferred until the derived operations
are accepted.

**Agreed minimal derived set (2026-09-07):**

| FR | Operation (derived) | Status |
|----|---------------------|--------|
| FR-8 | подать заявку магазина | **Accepted** |
| FR-9 | обработать заявку (отпуск товаров со склада в магазин) | **Accepted** |
| FR-10 | просмотреть заявки | **Accepted** |

Rationale: обработка заявки и отпуск — одна операция, не две («обработать» = отпустить:
складское количество уменьшается, количество в магазине увеличивается, заявка отмечается
обработанной). Прямое перемещение склад→магазин без заявки исключено из минимального
набора (все перемещения домена идут через заявки; parked as a future idea).

Semantics of «текущий год» (agreed): заявка текущего года — заявка, поданная в текущем
календарном году (дата подачи по A-3). Пересортировки/удаления заявок при смене года
не требуется: старые заявки сохраняются и просто перестают попадать под определение
«текущего года» (history preserved, no destructive rollover operation).

## 3. Global assumptions (A)

### A-1

«Единственный пользователь системы — сотрудник отдела снабжения оптовой базы».

### A-2

«Оптовая база имеет один склад; товары на складе образуют складской список».

### A-3

«Система имеет доступ к текущей дате».

*Принято при планировании FR-8 (2026-09-07): первое упоминание времени в домене —
«заявки на текущий год»; источник года — системная дата в момент подачи заявки.
Ранее принятые FR-1…FR-6 системную дату не используют.*

## 4. Definitions (D)

### D-1. Обработанное название

«Обработанное название — это введённое название без начальных и конечных пробелов».

## 5. Business rules (BR)

### BR-1

«Обработанное название (D-1) содержит хотя бы один символ».

*Редакция 2 (2026-09-07, FR-3): обобщено — слово «товара» убрано, правило применяется
ко всем названиям (товар, магазин). Редакция 1 (FR-1): «Обработанное название (D-1)
товара содержит хотя бы один символ».*

### BR-2

«Обработанное название (D-1) товара не совпадает (без учёта регистра) ни с одним
названием товара из складского списка».

### BR-3

«Товар может быть удалён из складского списка, только если его количество на складе
равно нулю».

### BR-4

«Обработанное название (D-1) магазина не совпадает (без учёта регистра) ни с одним
названием магазина из списка магазинов».

### BR-5

«Количество поступления — целое число, большее нуля».

### BR-6

«Количество запрашиваемого товара — целое число, большее нуля».

### BR-7

«Заявка может быть обработана, только если количество запрашиваемого товара из заявки
не превышает количества этого товара на складе».

### BR-8

«Магазин может быть удалён из списка магазинов, только если нет заявок со статусом
«подана», ссылающихся на этот магазин».

## 6. Functional requirements (FR)

### FR-1. Включить новый товар в список товаров на складе

Original wording: «включить новый товар в список товаров на складе».

«Сотрудник отдела снабжения (A-1) вводит название товара. Введённое название
обрабатывается согласно D-1. Если нарушается BR-1 или BR-2 — операция отклоняется:
складской список не изменяется, выводится сообщение об ошибке, соответствующее
нарушенному правилу. Если BR-1 и BR-2 выполняются — в складской список добавляется
товар: его обработанное название (D-1) и количество, равное 0».

### FR-2. Удалить ненужный товар из складского списка

Original wording: «удалить ненужный товар из складского списка».

«Сотрудник отдела снабжения (A-1) вводит название товара. Введённое название
обрабатывается согласно D-1. Если нарушается BR-1 — операция отклоняется. В складском
списке ищется товар, чьё название совпадает с обработанным введённым названием
(без учёта регистра). Если такой товар не найден — операция отклоняется. Если товар
найден, но нарушается BR-3 — операция отклоняется. Во всех случаях отказа складской
список не изменяется, выводится сообщение об ошибке, соответствующее причине отказа.
Если товар найден и BR-3 выполняется — товар удаляется из складского списка».

Примечание: «ненужный» в формулировке операции — решение актёра, системой не проверяется.

### FR-3. Включить новый магазин в список магазинов

Original wording: «включить новый магазин в список магазинов».

«Сотрудник отдела снабжения (A-1) вводит название магазина. Введённое название
обрабатывается согласно D-1. Если нарушается BR-1 или BR-4 — операция отклоняется:
список магазинов не изменяется, выводится сообщение об ошибке, соответствующее
нарушенному правилу. Если BR-1 и BR-4 выполняются — в список магазинов добавляется
магазин: его обработанное название (D-1)».

Примечание: на Phase 0 магазин имеет только название — других атрибутов методичка
не требует. Дополнительные атрибуты могут появиться только как отдельное решение
(extensions / future ideas), а не как молчаливое расширение FR-3.

### FR-4. Удалить ненужный магазин из списка

Original wording: «удалить ненужный магазин из списка».

«Сотрудник отдела снабжения (A-1) вводит название магазина. Введённое название
обрабатывается согласно D-1. Если нарушается BR-1 — операция отклоняется. В списке
магазинов ищется магазин, чьё название совпадает с обработанным введённым названием
(без учёта регистра). Если такой магазин не найден — операция отклоняется. Если магазин
найден, но нарушается BR-8 — операция отклоняется. Во всех случаях отказа список
магазинов не изменяется, выводится сообщение об ошибке, соответствующее причине отказа.
Если магазин найден и BR-8 выполняется — магазин удаляется из списка магазинов».

Примечания: «ненужный» в формулировке операции — решение актёра, системой не проверяется.
Гард BR-8 введён при закрытии OP-1 (2026-09-07): удаление блокируют только заявки
со статусом «подана»; обработанные заявки могут ссылаться на удалённый магазин —
название магазина сохранено в заявке (неактивная история).

### FR-5. Учесть поступление некоторого товара на склад

Original wording: «учесть поступление некоторого товара на склад».

«Сотрудник отдела снабжения (A-1) вводит название товара и количество поступления.
Введённое название обрабатывается согласно D-1. Если нарушается BR-1 или BR-5 —
операция отклоняется. В складском списке ищется товар, чьё название совпадает
с обработанным введённым названием (без учёта регистра). Если такой товар не найден —
операция отклоняется. Во всех случаях отказа складской список не изменяется,
выводится сообщение об ошибке, соответствующее причине отказа. Если товар найден —
количество товара на складе увеличивается на количество поступления».

Примечания: единица количества — целая (штучная) единица; дробное, нулевое
и отрицательное значения отклоняются (BR-5). Поступление с отрицательным количеством
не используется как уменьшение складского количества: отпуск товара будет
формализован при рассмотрении заявок магазинов — см. OP-2 (Section 9).

### FR-6. Просмотреть информацию о товарах на складе

Original wording: «просмотреть информацию о товарах на складе».

«Сотрудник отдела снабжения (A-1) просматривает складской список. Для каждого
товара складского списка отображаются его обработанное название (D-1) и количество
товара на складе. Товары отображаются в порядке алфавита по обработанному названию
(без учёта регистра). Если складской список пуст, отображается пустой результат;
это не является ошибкой».

Примечание: операция не изменяет складской список, не имеет ввода и веток отказа;
пустой складской список — допустимое состояние (не ошибка).

### FR-8. Подать заявку магазина

Derived operation (Section 2.1): домен требует «иметь точные данные о заявках магазинов
на текущий год»; среди семи исходных операций подача заявки отсутствует — восстановлено
по описанию домена и пункту «Разработать: модули ввода…».

«Сотрудник отдела снабжения (A-1) вводит название магазина, название товара и количество
запрашиваемого товара. Введённые названия обрабатываются согласно D-1. Если нарушается
BR-1 (для любого из названий) или BR-6 — операция отклоняется. В списке магазинов ищется
магазин, чьё название совпадает с обработанным введённым названием (без учёта регистра);
если магазин не найден — операция отклоняется. В складском списке ищется товар, чьё
название совпадает с обработанным введённым названием (без учёта регистра); если товар
не найден — операция отклоняется. Во всех случаях отказа данные не изменяются,
выводится сообщение об ошибке, соответствующее причине отказа. Если магазин и товар
найдены и BR-6 выполняется — создаётся заявка: система назначает ей номер (уникальный
среди всех ранее назначенных номеров заявок), фиксирует дату подачи согласно A-3,
устанавливает статус «подана» и состав: магазин, товар и количество запрашиваемого
товара».

Примечания: непрерывность нумерации (без пропусков) не требуется — только уникальность;
«подряд от 1, шаг +1» — деталь реализации. Количество заявки не ограничивается текущим
остатком на складе: остаток проверяется при обработке заявки (FR-9). Дублирующиеся
заявки (одинаковый магазин, товар и количество) допускаются — уникальность живёт только
в номере заявки.

### FR-9. Обработать заявку (отпуск товаров со склада в магазин)

Derived operation (Section 2.1): отпуск со склада в магазин отсутствует среди семи
исходных операций, восстановлен по описанию домена («о названии и количестве каждого
вида товара в каждом магазине») и пункту «Разработать: модули … изменения … данных».

«Сотрудник отдела снабжения (A-1) вводит номер заявки. Если заявка с таким номером
не найдена — операция отклоняется. Если статус заявки не «подана» — операция
отклоняется (заявка уже обработана). Если магазин заявки не найден в списке
магазинов или товар заявки не найден в складском списке — операция отклоняется.
Если нарушается BR-7 — операция отклоняется. Во всех случаях отказа данные
не изменяются, выводится сообщение об ошибке, соответствующее причине отказа.
Если все условия выполняются — изменения происходят как единое целое (все или
ничего): количество товара на складе уменьшается на количество запрашиваемого
товара из заявки, количество этого товара в магазине заявки увеличивается на ту
же величину (если товара в этом магазине ещё не было — его количество в этом
магазине становится равным количеству из заявки), статус заявки становится
«обработана», фиксируется дата обработки согласно A-3».

Примечания: у заявки два статуса — «подана» и «обработана»; отказ операции не меняет
статус заявки. Частичное выполнение не вводится: при недостатке остатка — полный
отказ (BR-7), обходной путь — новая заявка на доступное количество. Количество
товара в магазине — новая величина домена (Section 2.1): впервые создаётся
операцией FR-9.

### FR-10. Просмотреть заявки

Derived operation (Section 2.1): домен требует «иметь точные данные о заявках магазинов
на текущий год»; модуля просмотра заявок нет среди семи исходных операций — восстановлен
по пункту «Разработать: модули … просмотра данных» и эксплуатационной необходимости:
вход FR-9 — номер заявки, без просмотра сотрудник не может узнать номера.

«Сотрудник отдела снабжения (A-1) просматривает заявки. Для каждой заявки отображаются:
номер, статус, дата подачи, название магазина, название товара, количество запрашиваемого
товара; для заявки со статусом «обработана» — также дата обработки. Заявки отображаются
в порядке возрастания номера. Если заявок нет, отображается пустой результат; это не
является ошибкой».

Примечание: операция не изменяет данные, не имеет ввода и веток отказа; отображаются
все заявки, включая прошлые годы (история сохраняется сознательно; фильтр по году —
будущее уточнение).

## 8. Project extensions and future ideas
Project extensions: none implemented yet.

Extension candidates (agreed as future work, not committed):

- частичное выполнение заявки (отпуск доступного количества; потребовало бы поля
  «фактически отпущено» и нового статуса); отложено при FR-9 — обходной путь:
  новая заявка на доступное количество;
- многопозиционные заявки (несколько товаров в одной заявке); отложено при
  планировании FR-8 (EL-11).

## 9. Open points (OP)

### OP-1

При формализации заявок магазинов (после FR-7) пересмотреть условия удаления магазина
из списка магазинов: возможный гарда — наличие у магазина необработанных заявок.

Status: **closed** (2026-09-07) — сформулирован **BR-8** (удаление блокируют заявки
со статусом «подана»; EL-19), FR-4 обновлён со ссылкой на BR-8
Заведено при принятии FR-4: выбран вариант «FR-4 без гарда + явная открытая точка»
вместо правила на ещё не формализованной сущности (forward reference). Status: **open**.

### OP-2

При формализации заявок магазинов и отпуска товаров (после FR-7) предусмотреть
уменьшение складского количества: количество отгрузки — положительное целое число,
не превосходящее остаток товара на складе.

Мотивация: в рамках семи исходных операций складское количество только увеличивается
(FR-5), поэтому товар с ненулевым количеством не может быть удалён (BR-3). Гард
«по модулю не превосходит остаток» (предложен разработником при FR-5) сохранён здесь
в форме, корректной для отгрузки: вводится положительное количество. Отрицательное
поступление как «уменьшение склада» отвергнуто — это скрытая новая операция,
отсутствующая в задании. Status: **closed** (2026-09-07) — реализовано FR-9:
складское количество уменьшается, количество из заявки уже положительно (BR-6)
и не превосходит остаток (BR-7).
